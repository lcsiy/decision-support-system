## 1. 问题描述

2026-08-19 14:33 短线分析定时任务输出：

```json
"market_env": {
  "sh_close": 3990.3037,   // ← 这是 8/18 的收盘价，不是今天的
  "sh_ma20": 3886.01,
  "sh_change_pct": 0.19,   // ← 8/18 的涨跌幅
  "sentiment": "slightly_bullish",
  "market_score": 63.4,
  ...
}
```

而当天盘中上证及科技股大幅下挫（寒武纪 -9%、中际旭创 -8.3% 等）。DSS 的"偏多"结论
与实时盘面完全相反，**原因是它读的是上一交易日（8/18）的日线收盘数据**。

### 1.1 现有数据证明（2026-08-19 实测）

| 数据源 | 接口 | 盘中实时性 | 权限/实测结果 |
|---|---|---|---|
| `swing_orchestrator._assess_market()` | `index_daily`（日线） | ❌ 盘中取到的是上一交易日 | ✅ 返回 8/18 收盘 |
| `tushare_client.get_market_environment()` | `get_tushare_index_daily`（日线） | ❌ 同上 | ✅ 同上 |
| 分钟采集器 `minute_collector` | `get_realtime_quotes`（旧实时接口） | ✅ 有实时 | ✅ 实测可用（采集个股） |
| 个股实时行情 | `rt_min` | ✅ | ✅ 实测可用（本 session 已证） |
| 指数实时行情 | `rt_idx_min` | ✅ 理论上 | ❌ **无权限（40203）** |
| 指数实时日K | `rt_idx_k` / `rt_k` | ✅ 理论上 | ❌ **无权限（40203）** |
| 大盘资金流 | `moneyflow_mkt_dc` | 日级 | ⚠️ 低频，未验证今日 |

**核心结论**：市场环境评估当前**只依赖日线接口**，盘中运行时取到的是最近一根已收盘的
日线（昨天）。它本身能"运行成功"（不报错），但拿的是过期数据，导致评分与实时盘面失真。

## 2. 根因分析

### 2.1 直接原因

`swing_orchestrator.py` 的 `_assess_market()` 逻辑：

```python
idx_df = self.tushare.index_daily(
    ts_code='000001.SH',
    start_date=self.tushare.days_ago_str(60),   # 60 天前
    end_date=self.tushare.today_str(),           # 今天
)
# 评分只看收盘价 vs MA20
close = idx_df['close'].values
sh_close = float(close[-1])                       # ← 盘中时是昨天的收盘
```

`index_daily` 是**日线**接口，其"最后一根"在交易时段内还未生成今日 K 线，故
`close[-1]` 实为上一交易日收盘。所有基于它的 `sh_close`、`sh_change_pct`、`price_vs_ma`、
`market_score`、`base_sentiment` 全部滞后一个交易日。

### 2.2 为什么没报错却没被发现

- 数据请求成功（不抛异常），系统无从感知"数据已过期"。
- `_assess_market()` 结果被各模块（`swing_pool`、LLM `risk_manager`、`swing_trader`）
  当作"今日市场环境"直接消费，无任何新鲜度校验。
- 只要不是明显崩溃的交易日，昨日收盘与今日常常差异不大，问题具有隐蔽性；今天这种
  极端分化/崩塌才暴露出来。

### 2.3 影响面

| 消费方 | 位置 | 影响 |
|---|---|---|
| 市场情绪/评分 | `_assess_market` 返回值 | 直接失真（本 bug） |
| 池内卖出风险评估 | `swing_pool._assess_market_risk` | 用过期情绪判断系统风险 |
| LLM 卖出/买入上下文 | `risk_manager`、`swing_trader`、`news_analyst` | 基于过期市场描述做推理 |
| 尾盘分析（同源） | `tushare_client.get_market_environment` | 同上 |

## 3. 方案目标

在不破坏现有调用方接口的前提下，让"市场环境评估"在**盘中**使用当日实时/盘中数据，
在**非交易时段**回退到日线收盘，并对数据新鲜度显式标注。原则：

1. **盘中优先实时**：交易时段内市场评分应基于当日实时指数，而非昨日收盘。
2. **非交易时段回退日线**：收盘后/盘前用最近一根完整日线（此时它就是"今日"）。
3. **新鲜度显式化**：返回 `data_source` / `is_intraday` / `used_trade_date` 等字段，
   让下游和读报告的人一眼看出用的是实时还是日线。
4. **可降级**：实时数据源任一失败时，不影响整体运行（沿用现有容错风格）。

---

## 4. 数据源选型（关键前提）

要"盘中拿当日实时指数"，需要**能被当前 token 权限访问的实时指数通道**。实测现状：

- ❌ `rt_idx_min` / `rt_idx_k`：**无权限（40203）** —— 若选它，需提升积分或不可用。
- ✅ `ts.get_realtime_quotes(['sh000001', ...])`：**可用**（分钟采集器正在用同一通道），
  指数代码带交易所前缀（`sh000001` = 上证、`sz399001` = 深成、`sz399006` = 创业板）。
  ⚠️ 前提：需验证该旧接口对**指数代码**是否返回有效"当前价 + 涨跌幅"，与个股同源。

### 4.1 首选方案（推荐验证路径）

**用 `get_realtime_quotes(sh000001/sz399001/sz399006)` 拉当日实时指数**
（与分钟采集器同通道，已证明 token 可访问），盘中据此算分；不足时回退日线。

### 4.2 备选方案（若 4.1 指数不通）

- **A. 积分提升后启用 `rt_idx_min/rt_idx_k`**：官方实时接口，数据规范，但当前无权限。
- **B. 盘中合成代理指标**：用 `rt_min` 拉一批有代表性的权重/热门股现价，聚合成"盘中
  大盘代理涨跌幅"，作为评分输入（精度一般，需谨慎标注为代理指标）。
- **C. 仅做标注不换数据**（最小改动）：保守起见不改数据源，只在报告里显式标注
  `data_source=日线-前收`，避免用户误读。可作为"过渡/兜底"。

> 建议交付顺序：**先验证 4.1 指数代码可用性**（一次小脚本），可用则主推；不可用则
> 落到 A（提权）或 C（标注）。

## 5. 具体修改方案

### 5.0 前置：数据源可用性探针（先做，1 个脚本）

新建一次性脚本 `scripts/probe_realtime_index.py`（不并入主流程，仅验证）：

```python
# 验证 get_realtime_quotes 对指数代码是否返回有效实时价
from dss.config import Config
from dss.data_layer.tushare_client import TushareClient

c = TushareClient(Config())
df = c.get_realtime_quotes(['sh000001', 'sz399001', 'sz399006'])
print(df[['code', 'name', 'price', 'pre_close', 'change', 'changepct']])
```

判定标准：`price` 非 0、`changepct` 非空、且盘中能反映当日波动（对照 rt_min 数据）。
→ 结果决定走 5.1 主方案还是 5.1B/5.1C 备选。

### 5.1 核心改动：`swing_orchestrator._assess_market()`（高层）

改造逻辑（接口不变，返回值增强）：

```python
def _assess_market(self) -> Dict[str, Any]:
    # 1) 先按交易时段判断是否盘中
    is_intraday = self._is_trading_session()

    # 2) 若盘中 → 优先实时指数
    intraday = self._try_intraday_market()   # 用 get_realtime_quotes 指数
    if is_intraday and intraday['ok']:
        res = self._score_from_intraday(intraday)   # 现价 vs MA20 + 当日涨跌幅
        res['data_source'] = 'realtime'
        res['is_intraday'] = True
        return res

    # 3) 否则/失败 → 回退日线（原逻辑），并标注数据日期
    res = self._score_from_daily()           # 原逻辑抽成函数
    res['data_source'] = 'daily'
    res['is_intraday'] = False
    res['used_trade_date'] = <最新日线日期>
    return res
```

关键点：
- **一致性**：实时与日线两条路径都产出同一组字段（`sh_close` / `sh_ma20` / `sh_change_pct`
  / `sentiment` / `market_score` / `base_sentiment` / `turnaround`），下游零改动。
- **MA20 基准**：MA20 仍用日线回看 60 天算（基准不该用盘中，避免跳动），只有
  `sh_close`（现价）和 `sh_change_pct`（当日涨跌）用实时；`price_vs_ma` 用实时现价 vs 日线 MA20。
- **降级**：任何一步失败 → 走日线路径，绝不抛异常阻断主流程。

### 5.2 数据层：`tushare_client.py` 新增实时指数方法（中层）

在 `TushareClient` 增加（复用现有 `get_realtime_quotes` 通道）：

```python
def get_intraday_index(self, codes=None) -> Optional[pd.DataFrame]:
    """盘中实时指数行情（与分钟采集同通道）。
    指数代码需带前缀：sh000001 / sz399001 / sz399006"""
    codes = codes or ['sh000001', 'sz399001', 'sz399006']
    return self.get_realtime_quotes(codes)  # 复用，验证指数字段后封装

def get_intraday_index_change(self, code='sh000001') -> Tuple[float, float]:
    """返回 (实时点位, 当日涨跌幅%)；失败返回 (None, None)"""
```

### 5.3 新鲜度显式化（横切改造）

- `_assess_market()` 返回值新增：
  - `data_source: 'realtime' | 'daily'`（今日数据来源）
  - `is_intraday: bool`（是否盘中）
  - `used_trade_date: str`（实际采用的行情日期，如 `20260819` 或 `20260818`）
- 报告/日志打印：`📊 市场评分: 63.4 (slightly_bullish) [实时 20260819]` 或
  `[日线 20260818]`，让人一眼辨新鲜度。
- `get_market_environment()`（尾盘同源逻辑）同步加字段，保持一致。

### 5.4 配置化开关（可选）

在 `.env` 增加：

```bash
MARKET_INTRADAY_ENABLED=true   # 盘中是否启用实时指数；false=始终日线（旧行为）
MARKET_INTRADAY_FALLBACK=true  # 实时失败时是否回退日线
```

默认 `true/true`，可随时关回旧行为，方便 A/B 对比。

## 8. 附：本次问题复盘要点（教训）

1. **市场环境数据新鲜度缺失**：`index_daily` 盘中命中"最后一根=昨日"，且无任何新鲜度
   校验或标注，导致"运行成功但数据过期"。
2. **同源双逻辑**：`swing_orchestrator._assess_market` 与 `get_market_environment` 都依赖
   日线，需一并修，避免只修一处。
3. **实时指数通道权限**：`rt_idx_min/rt_idx_k` 无权限；`get_realtime_quotes` 有权限且已用于
   分钟采集，是当前最可行的盘中指数来源，但需先验证其对指数代码的兼容性。

### 额外发现并修复（同批）
1. **LLM 输出字段漂移（深层根因）**: LLM 实际输出 `decision/final_confidence/key_factors` 而非约定 `verdict/confidence/reasoning`，`_parse_result` 全部读空 → 默认 HOLD → **LLM 判了 SELL 却静默执行成"继续持有"**（历史"盈利变亏损"的主因之一）。已做字段名兼容解析（`_VERDICT_KEYS` 等映射）。
2. **列表字段类型防护**: LLM 可能输出 dict 列表，`', '.join()` 崩溃 → `_fmt()` 统一转字符串。
3. **卖出裁决上下文增强**: `review_sell_signal` 新增 `hold_days_ref`/`highest_price` 注入（持仓时间成本 + 浮盈回撤），Risk Manager 决策矩阵新增"短线资金效率原则"。
4. **ATR 评分改为倒钟形**（短线偏好 2.5-5% 波动区间，死水 <1.2% 降分）——解决"全选低波动股票"问题（保持主板不放开）。
